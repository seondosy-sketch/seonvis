## 2026-09

### 프로젝트 상세 모달에 평가 결과·참여 기술인 추가
- 프로젝트 List에서 용역명을 눌러 여는 공고 상세 모달에 **평가 결과**(결과 등급·낙찰사·낙찰액 + 상태 배지)를 추가했다. 표에는 열로 있던 값인데 상세에는 하나도 없어서, 상세만 열어서는 그 공고가 어떻게 끝났는지 알 수 없었다(78건 중 결과 등급 67건·낙찰사 65건에 값이 있다). 값이 하나도 없는 공고에서는 섹션을 만들지 않는다
- **참여 기술인** 섹션 추가 — `project_participants` 행(출근부·면접 DB와 같은 소스)과 손입력 `staff_*` 텍스트를 **합쳐** 보여준다. 둘 중 하나만 채워진 프로젝트가 많아(행 30건 / 텍스트 47건) 어느 한쪽만 보여주면 아는 정보가 사라진다. 합치는 규칙은 순수 함수 `lib/projects/staffSummary.ts`
  - 단장이 맨 앞, 그다음 배치 순서. 텍스트에만 있는 이름은 `입력` 꼬리표로 주소록 연결과 구분한다. 같은 사람이 양쪽에 있으면 한 번만 나온다(표기 차이 흡수)
  - 상단 표의 `분야기술자` 줄은 뺐다 — 이 섹션이 그 텍스트를 포함하므로, 남기면 `분야기술자 -` 아래에 실제 기술인이 나오는 모순이 생긴다. 빈 칸이 생기지 않게 나머지 항목을 2열로 다시 짝지었다
  - 참여기술인은 모달을 열 때 그 프로젝트 것만 읽는다(목록 전체를 미리 읽지 않는다)
- 개찰일은 평가 결과 섹션에 넣지 않는다 — 같은 모달의 `입찰 일정` 섹션에 이미 있다

### CM업계소식(CMAK) 연동 복구 — 협회 사이트 개편 대응
- 메인 대시보드 CM업계소식이 비어 있던 원인은 한국CM협회 사이트 개편이다. 옛 주소가 새 주소로 302되면서 목록 URL·상세 URL·인코딩·표 마크업이 한꺼번에 바뀌었다
  - 목록 `/html/notice/news.asp` → `/notice/news`, 상세 `.../news_r.asp?...&no={idx}` → `/board/news_domestic/{idx}`
  - 인코딩 **EUC-KR → UTF-8**, 목록 마크업 `go_Edit('idx')` onclick → `<a href>`
  - `fetch`가 리다이렉트를 따라가 HTML은 받아왔지만 EUC-KR로 디코딩해 한글이 깨지고 정규식이 0건이 됐다. 옛 상세 링크는 기사가 아니라 목록으로 튕겨서 클릭도 동작하지 않았다
- **기사 상세 URL을 서버(`app/api/cmak-news/route.ts`)가 만들어 내려준다.** 대시보드가 URL을 조립하던 코드를 없애 다음 개편 때 고칠 곳을 한 파일로 모았다
- **파싱 결과가 0건이면 502로 알린다.** 이번 breakage를 몇 주간 못 알아챈 이유가 "0건 → 빈 화면"이었다. 페이지는 받았는데 한 건도 못 뽑으면 서식 변경으로 보고 에러를 돌려준다
- 실제 응답 HTML의 표 부분을 fixture로 저장해 파서를 단위테스트한다(`app/api/cmak-news/route.test.ts`, 옛 `go_Edit` 서식이 0건이 되는 것까지 고정)

### 면접 DB — 후기 HWP 파일을 올려 등록 폼에 채우기
- 면접 DB(`/interviews`) 면접후기 탭에 **"HWP 후기 올리기"** 추가. HWP·HWPX 후기 문서를 올리면 발주처·용역명·시설용도·일시·장소·면접관·참가업체·참석자·진행방법·특이사항·실제질의를 읽어 **등록 폼에 채워** 준다. 여러 파일을 한 번에 올리면 한 건씩 순서대로 확인한다
- **읽기만으로는 DB에 아무것도 저장되지 않는다.** 문서 서식이 연도·작성자마다 달라 파싱이 틀릴 수 있으므로 사람이 값을 확인하고 `저장`을 눌러야 등록된다(저장 경로는 기존 `save_evaluation_review` RPC 그대로 — 새 저장 경로를 만들지 않았다)
- 파싱은 순수 함수 두 개로 나눠 뒀다. `lib/evaluations/hwpImport.ts`가 문서에서 **글자**만 뽑고(kordoc·DB 의존 없음), `lib/evaluations/importSeed.ts`가 그 글자를 마스터 id로 잇는다(평가유형·질의그룹·프로젝트·기술인)
- 확실하지 않으면 잇지 않는다 — 같은 이름 후보가 둘 이상인 프로젝트·기술인은 비워 두고, 못 읽은 라벨·못 정한 질의그룹은 폼 상단에서 사람에게 알린다. **질의분류(주제)는 추론하지 않고 전부 '미지정'으로 시작**(사용자가 추측한 값이 정식 분류축이 되는 것을 막는 기존 정책 유지)
- 실제 후기 문서(한전 변전소 면접후기 2건)로 서식을 맞췄다. 그 문서에서 배운 것들:
  - 개요와 질의가 **표 하나**에 들어 있고 머리행이 `구 분 | 내 용`이다. '구분'·'내용'을 항목 라벨로 인정하면 개요 표 전체가 질문으로 읽히므로 그 낱말은 라벨 사전에서 제외했다(`IGNORED_LABELS`) — 회귀 테스트로 고정
  - 라벨을 "발 주 처", "일    시"처럼 벌려 적고, 특이사항 라벨에는 `특이사항\n(분위기, 좌석배치 등)`처럼 줄바꿈·괄호 설명이 붙는다 → 라벨 정규화가 공백·꼬리 콜론·꼬리 괄호를 벗긴다
  - 항목 이름이 **면접방법**·**주요질의내용**이다(진행방법·실제질의가 아니다) → 라벨 사전에 추가
  - **평가유형 칸이 아예 없다.** 제목("345kV ○○변전소 면접후기")에 평가유형 이름이 들어 있으면 그것을 읽고 "제목에서 읽었다"고 알린다. 칸이 있는데 표준 유형에 없는 원문이면 제목으로 덮어쓰지 않는다
  - 참석자를 "조장연 상무(단장)", "이상원(65) 상무(건축)"처럼 적는다 → 역할은 **맨 뒤 괄호**에서 읽고, 주소록 연결은 직급을 뗀 이름으로도 시도한다(문서 표기는 스냅샷에 그대로 보존)
  - 시설용도 칸이 없어 매번 직접 입력해야 하므로 그 사실을 폼에서 알린다(질의 검색 필터 축이라 비워 두면 나중에 안 걸린다)
- 연도만 적힌 과거 문서는 가짜 월·일을 만들지 않고 `evaluation_year`로 남긴다. 사용자가 다른 해의 평가일을 채우면 어긋나는 연도를 버려 DB CHECK 위반을 막는다(`lib/evaluations/reviewPayload.ts`)
- 서버 라우트 `app/api/interviews/import/route.ts`는 kordoc으로 문서를 읽어 초안 JSON만 돌려준다. 세션 + `menu_permissions.interview_db === 'write'`를 서버에서 다시 확인하고, 20MB·확장자(.hwp/.hwpx) 제한을 둔다. DB 쓰기는 없다
- 마이그레이션 없음(테이블·컬럼 변경 없음). 검증: 단위테스트 `lib/evaluations/hwpImport.test.ts` · `importSeed.test.ts` · `reviewPayload.test.ts`, UI 자동검증 `e2e/interviews.import.spec.ts`(합성 후기 문서 fixture, 저장하지 않음)

- 기준: **프로젝트 List의 공사번호 오름차순**. 비교 로직은 `lib/projectOrder.ts` 한 곳(`compareProjectNumber` / `byProjectNumber`)
- 예전에는 화면마다 제각각이었다 — 대부분 공사번호 **내림차순**, 출장지원은 **발표일순**, 숙소 프로젝트 선택은 **용역명순**
- 적용: 주간/월간보고(화면 + **HWPX 출력물**), 출장지원, 출근부, 연장근무(화면 + 인쇄물 + 프로젝트 관리), 숙소, 메인 달력, 홈 위젯, 미래봇
- 주간/월간보고는 저장된 행까지 다시 줄 세우고 `sort_order`를 재부여 — 화면·저장·HWPX 순서가 항상 일치. 지난주 복사도 같은 순서로 다시 세운다
- 연장근무는 `source_project_id`로 공사번호를 찾아 정렬(`lib/overtime/projectOrder.ts`). 입찰 List에 없는 수동 등록 행은 뒤쪽에 모여 기존 `sort_order` 순서를 유지하고, 연계 행의 정렬순서 입력칸은 쓰이지 않으므로 비활성 처리
- 공사번호는 text라 자릿수·접두어가 섞여도 사람이 기대하는 순서가 나오도록 숫자 인식 비교(`numeric: true`) 사용. 번호 없는 행은 맨 뒤
