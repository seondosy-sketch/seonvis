# 홈화면 위젯 (아이폰 · 안드로이드)

미래Hub의 **이번 주 일정**을 휴대폰 홈화면에 띄우는 기능. 앱 설치나 스토어 배포 없이,
서버가 그려주는 **위젯 모양 PNG 이미지 한 장**을 위젯 앱이 주기적으로 가져가는 구조다.

- 설정 화면: 미래Hub 사이드바 맨 아래 **📱 홈화면 위젯** → `/widget`
- 이미지 엔드포인트: `GET /api/widget/summary?token=…&size=…&theme=…`

---

## 왜 이미지인가

iOS·Android의 홈화면 위젯은 OS가 네이티브 코드로만 그리게 되어 있어서 웹앱(Next.js)을 그대로
위젯으로 만들 수 없다. 선택지는 세 가지였다.

| 방식 | 장점 | 단점 |
|------|------|------|
| PWA (홈화면 아이콘) | 가장 쉬움 | 아이콘일 뿐 — 홈화면에 내용이 안 보임 |
| **이미지 위젯 (채택)** | 구현 하나로 iOS·Android 동일, 디자인을 서버에서 100% 제어 | 위젯 안에서의 인터랙션이 없다(탭은 앱·브라우저로 넘어가는 동작뿐), 갱신 주기는 OS·위젯 앱이 정한다 |
| 네이티브 앱 + WidgetKit/Glance | 푸시·오프라인·인터랙션 전부 가능 | iOS 사내 배포(Apple Developer 계정) 필요, 수 주 규모 |

## 담긴 내용

- 이번 주 **제출 · 발표 · 개찰** 일정 (대시보드 홈의 주간 달력과 같은 데이터)
- 이번 주 **팀 일정**(`team_events`, 등록한 색 그대로) · **공휴일**
- 헤더에 종류별 주간 합계, 푸터에 데이터 기준 시각(KST)

작은/보통 위젯은 **오늘 이후 남은 일정만**, 큰 위젯은 **지난 요일까지 흐리게 포함한 주 전체**를
보여준다. 오늘 행은 테두리·배경으로 강조되고, 왼쪽 아래에 `업데이트 HH:MM`(KST)이 찍힌다.

### 파라미터

| 파라미터 | 값 | 설명 |
|---------|-----|------|
| `token` | `wgt_…` | 필수. 설정 화면에서 발급 |
| `size` | `small`(474×474) · `medium`(1014×474, 기본) · `large`(1014×1062) | iOS 위젯 실측 비율 ×3 |
| `theme` | `light`(기본) · `dark` | |
| `t` | 아무 값 | 서버는 **무시한다**. 헤더를 무시하고 캐시하는 OS·앱을 대비해 클라이언트가 붙이는 값 |

## 갱신 정책 — "자동은 느슨하게, 필요할 때 확인"

실시간 갱신을 쫓지 않는다. 자동 갱신은 1~3시간 간격으로 낮게 두고, 최신 정보가 필요한 순간의
동작은 **기종에 따라 다르다**(아래). 이 차이를 설정 화면 안내문에도 그대로 적어 두었다.

### 플랫폼별 실제 동작과 한계 (조사 결과)

| | iOS (Scriptable) | Android (이미지 위젯 앱) |
|---|---|---|
| 자동 갱신 | `refreshAfterDate`는 **"이 시각 이전엔 갱신 안 함"이라는 하한선 요청**일 뿐 정시 갱신을 보장하지 않는다. 배터리 상태·위젯을 보는 빈도에 따라 iOS가 더 늦춘다 | 위젯 `updatePeriodMillis`의 시스템 강제 **최소값이 30분**(더 짧게 넣으면 무시됨). WorkManager를 쓰는 앱은 15분 |
| 이 프로젝트 설정 | 스크립트가 **2시간 뒤**로 요청 | 앱 설정에서 **1~3시간** 권장 |
| 사용자 조작 | **탭 = 최신 일정 즉시 확인**. 위젯에 `url`을 지정하면 탭이 URL 열기로 덮어써지므로 `w.url`을 비우고 위젯 설정의 `When Interacting = Run Script`를 쓴다 → 스크립트가 앱에서 실행돼 방금 만든 이미지를 `QuickLook`으로 전체화면 표시 | **더블탭 = 홈화면 위젯 이미지 강제 갱신**(Web Image Widget 기준. 앱마다 이름이 다르다) |
| 홈화면 그림 | **탭해도 바뀌지 않는다.** iOS가 다음 타임라인 갱신을 허용하는 시점에 바뀐다 — Scriptable에는 위젯을 강제로 다시 그리게 하는 API가 없다. 그래서 아이폰의 탭은 "강제 갱신"이 아니라 **"지금 일정 보기"** 다 | 강제 갱신 시 홈화면 그림까지 바뀐다 |

### 캐시 — 어디에도 저장하지 않는다

이미지에는 프로젝트 제출일·발표일·개찰일과 팀 일정이 담긴다. 토큰별로 URL이 갈린다고 해도
**사내 일정 그림을 외부 CDN의 공개 캐시에 남기지 않는 것**을 원칙으로 삼아, 모든 응답을
`private, no-store`로 내린다(토큰이 무효한 안내 이미지도 동일).

그래서 **ETag/304도 두지 않는다** — `no-store`면 클라이언트가 응답을 보관할 수 없어 조건부
요청(If-None-Match)이 원리적으로 발생하지 않으므로, 남겨두면 절대 실행되지 않는 코드가 된다.
결과적으로 모든 요청이 "권한 확인 → DB 조회 → PNG 렌더"를 거친다.

**서버 내부 캐시도 두지 않았다.** 요약 데이터나 PNG를 짧게 메모이즈하면 렌더를 아낄 수 있지만,

- 팀 9명 × 자동 갱신 2시간 기준 요청량이 **월 수천 회** 수준이라 렌더 비용이 문제되지 않는다
- 내부 캐시를 두면 **토큰 해지·권한 회수 시점에 낡은 이미지가 남을 위험**(무효화 누락)이 생긴다
- 서버리스 환경에서는 인스턴스마다 캐시가 따로 생겨 적중률도 낮다

즉 이 규모에서는 캐시 절감보다 "항상 최신 + 무효화 사고 없음"이 이득이 크다. 훗날 요청량이
정말 문제가 되면 다음 순서를 지켜야 한다: ① 권한 확인(`resolveWidgetToken`)을 **먼저** 하고
② 토큰 원문이 아닌 **해시**를 캐시 키로 쓰고 ③ TTL을 짧게(수 분) 두고 ④ 토큰 해지·권한 변경 시
해당 키를 즉시 버린다.

### 업데이트 시각의 의미

이미지 좌하단 `업데이트 HH:MM`(KST)은 **그 PNG를 서버에서 만든 시각 = 같은 요청에서 일정을
DB에서 조회한 시각**이다. 휴대폰이 이미지를 받은 시각도, 화면에 그려진 시각도 아니다.

캐시·304를 쓰지 않으므로 "캐시된 그림인데 현재 시각처럼 보이는" 상황은 발생하지 않는다.
아이폰 홈화면 썸네일이 예전 그림이면 **예전 시각이 그대로 찍혀 있어** 얼마나 묵은 화면인지
바로 알 수 있다 — 이 문구의 목적이 그것이다.

### 서버 부담

가장 비싼 작업은 satori PNG 렌더다(요청당 약 0.1~0.5초).

- 자동 갱신 2시간 → 기기 1대당 **하루 약 12회**, 팀 9명이면 하루 100~200회 수준
- 사용자 조작(아이폰 탭 / 안드로이드 더블탭)은 누른 횟수만큼이라 예측 가능하다
- `last_used_at`은 **1시간 스로틀**이라 요청당 DB 쓰기는 0회에 가깝다 (권한 확인 SELECT는 매 요청)

## 설치 — 아이폰 (Scriptable)

1. App Store에서 **Scriptable**(무료) 설치
2. 미래Hub `/widget`에서 **Scriptable 코드 복사** (선택한 크기·배경이 코드에 반영된다)
3. Scriptable에서 **+** → 붙여넣기 → 스크립트 이름을 `미래Hub`로 저장
4. 홈화면 빈 곳 길게 누르기 → **+** → Scriptable → 원하는 크기 위젯 추가
5. 추가된 위젯 길게 누르기 → **위젯 편집** → Script를 `미래Hub`로, **When Interacting**을
   **Run Script**로 지정

스크립트는 `config.runsInWidget`으로 두 경로를 나눈다.

- **위젯에 그릴 때**: 기본 주소로 이미지를 받아 꽉 채우고(`applyFillingContentMode`),
  `refreshAfterDate`를 2시간 뒤로 둔다. `w.url`은 **일부러 비운다** — 지정하면 탭이 URL 열기로
  덮어써져 스크립트가 실행되지 않는다(탭할 때 미래Hub를 열고 싶으면 코드의 주석 한 줄을 해제).
- **탭해서 앱에서 실행될 때**: 최신 이미지를 받아 `QuickLook.present`로 전체화면에 띄운다.
  주소에 붙는 `&t=<타임스탬프>`는 서버가 쓰지 않는 값으로, OS가 `no-store`를 무시하고 캐시할
  경우를 대비한 클라이언트 측 우회용이다.

> **아이폰에서 탭은 "강제 갱신"이 아니다.** 전체화면으로 보이는 일정은 방금 조회한 최신이지만,
> 홈화면 위젯 그림 자체는 iOS가 다음 타임라인 갱신을 허용할 때 바뀐다.

## 설치 — 안드로이드

Play 스토어에서 **URL 이미지를 위젯으로 띄우는 앱** 하나를 설치하고, 이미지 주소에 위젯 URL을
넣으면 된다. 확인된 후보:

| 앱 | 패키지 | 비고 |
|----|--------|------|
| Web Image Widget | `com.ibuffed.webimagewidget` | 더블탭 강제 갱신, 크기 조절·이미지 스케일링 |
| Better URL Image Widget | `com.yktp.betterurlimagewidget` | 갱신 옵션이 유연함 |
| Live Image Widget | — | 갱신 주기 5분~6시간, Wi-Fi에서만 갱신 옵션 |

1. 앱에서 새 위젯 만들기 → **이미지 주소(URL)**에 설정 화면에서 복사한 위젯 주소 붙여넣기
2. 갱신 주기를 **1~3시간**으로 설정 (30분 미만은 시스템이 무시한다)
3. 탭 동작이 있으면 미래Hub 주소(`https://seonvis.vercel.app`)로 설정
4. 홈화면 빈 곳 길게 누르기 → 위젯 → 해당 앱 위젯 추가
5. 최신 정보가 필요할 때는 위젯 **더블탭** → 홈화면 위젯 이미지가 강제로 갱신된다
   (서버가 이미지를 어디에도 캐시하지 않으므로 항상 방금 조회한 일정이 온다)

가로로 긴 위젯에는 `medium`, 정사각형에는 `small`이 글자가 가장 크게 나온다.

## 보안

**주소 자체가 열쇠**다(`?token=`). 위젯 앱은 쿠키 세션을 들고 갈 수 없어서, 로그인 대신 토큰으로
신원을 확인한다. 그래서 이렇게 제한했다.

- 이미지에는 **이번 주 일정 요약만** 담긴다 — 원본 테이블이나 개인정보는 나가지 않는다
- 요청마다 `allowed_users`를 **다시 조회**한다 → 권한이 회수되거나 승인이 취소되면 토큰이 남아
  있어도 이미지가 막힌다(`lib/widget/token.ts`)
- `menu_permissions`에서 `weekly`·`projects`가 **모두 `none`**인 사용자에게는 프로젝트 일정을
  빼고 팀 일정·공휴일만 그린다
- 사용자당 활성 토큰은 1개. **재발급하면 기존 주소는 즉시 무효**가 된다 (유출 시 대응)
- **모든 응답이 `private, no-store`**다 — 사내 일정 그림이 외부 CDN 공개 캐시나 단말에 저장되지
  않는다. 서버 내부 캐시도 없으므로 토큰을 해지하거나 권한을 회수한 **직후 요청부터** 안내 이미지가
  나간다(낡은 이미지가 남아 다시 나갈 경로 자체가 없다)
- `last_used_at`은 "아직 쓰이는 위젯인지" 파악용 부가 정보라 **마지막 기록 이후 1시간이 지났을
  때만** 쓴다(`isStale`) — 요청마다 DB에 쓰지 않는다. 권한 확인(읽기)은 여전히 매 요청 수행한다

`proxy.ts`(Next 16의 미들웨어)에서 로그인 없이 통과시키는 경로는 `/api/widget/summary`와
`/fonts/*`뿐이다. 발급·해지(`/api/widget/token`)는 로그인 필수다.

## 구현 메모

| 파일 | 역할 |
|------|------|
| `app/api/widget/summary/route.tsx` | `next/og`(satori+resvg)로 PNG 렌더 · 크기/테마/레이아웃 · `private, no-store` |
| `app/api/widget/token/route.ts` | 토큰 발급(POST)·조회(GET)·해지(DELETE), 로그인 필수 |
| `app/(dashboard)/widget/page.tsx` | 설정 화면 — 발급/재발급/해지, 미리보기, 설치 안내 |
| `lib/widget/summary.ts` | 데이터 조립 + KST 날짜 계산 (`lib/widget/summary.test.ts`) |
| `lib/widget/token.ts` | 토큰 발급·검증 + 권한 재확인 + `last_used_at` 스로틀(`isStale`) |
| `lib/weekSchedule.ts` | 주차·일정 계산 — 대시보드 홈과 공유 |
| `supabase/migration_widget_tokens.sql` | `widget_tokens` 테이블 |

**한글 폰트**: satori는 시스템 폰트를 못 쓰므로 `public/fonts/NotoSansKR-{Regular,Bold}.ttf`를
직접 넣어야 한다(안 넣으면 한글이 통째로 빈칸). 6MB짜리라 모듈 스코프에 캐시해 콜드스타트당
1회만 읽고, 파일시스템 읽기가 실패하면 같은 오리진 HTTP로 폴백한다. 서버리스 번들에 폰트가
포함되도록 `next.config.ts`의 `outputFileTracingIncludes`에 명시했다.

**시간대**: 위젯은 UTC 서버에서 렌더되므로 `new Date()`를 그대로 쓰면 KST 월요일 오전에 지난
주가 나온다. 모든 날짜 기준을 `kstToday()`(KST 달력 날짜)에서 출발시키고, 이 경계를
`lib/widget/summary.test.ts`에서 검증한다.

**satori 제약**: flexbox만 지원하고 `display: grid`는 안 된다. 자식이 둘 이상인 `div`에는 명시적
`display`가 필요해서, 텍스트는 한 줄에 하나의 `div`로 두거나 템플릿 문자열로 합쳐야 한다.
