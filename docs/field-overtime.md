# 연장근무 (실무자)

> 제안서팀 연장근무(`/overtime`, [overtime.md](./overtime.md))와 별개인 실무자용 연장근무 화면. 경로 `/field-overtime`,
> 사이드바 근태관리 → `연장근무(실무자)`, 메뉴 권한 키 `field_overtime`.

## 제안서팀 버전과 다른 점

| | 제안서팀 (`/overtime`) | 실무자 (`/field-overtime`) |
|---|---|---|
| 입력 | 프로젝트·업무내용·시작/종료/휴게 | **직원·날짜·종료시간만** |
| 저장 단위 | 직원+날짜+프로젝트+업무 = 1건 | **직원+날짜 = 1건** (DB UNIQUE) |
| 한 달 | 전달 21일 ~ 20일 (급여 마감) | **달력 월 1일 ~ 말일** |
| 화면 | 직원×날짜 그리드 | 달력 + 주차별/월별 집계 탭 |
| 명단 | 둘 다 `overtime_employees` — 기술인 주소록 소속 `미래사업팀`에서 동기화 (아래 참고) | |

## 인정시간 규칙 (`lib/field-overtime/calc.ts`)

```
인정시간 = 종료시간 − 18:00 − 휴게 1시간, 1시간 단위 절삭(내림)
예) 21:00 → 2h, 22:30 → 3h(3.5 절삭), 24:00 → 5h, 19:30 → 인정 없음(저장 불가)
```

- 계산식은 제안서팀 팝오버 "기타" 유형과 같은 `calculateRecognizedHours`를 재사용한다(규칙 한 곳 관리).
- 종료시간은 텍스트 입력 — 자정을 넘기면 `25:00`처럼 24 이상으로 적는다. `2130`·`21` 같은 빠른 입력은
  `normalizeEndTime`이 `21:30`·`21:00`으로 정리한다.
- 시작·휴게는 고정이라 저장하지 않고 `end_time`과 계산된 `hours`만 저장한다.

## 휴일 근무 (휴가관리 일정 참고)

- 휴일 = 주말 + 휴가관리 `holidays` 테이블(법정공휴일·회사휴무). 공휴일 목록을 따로 두지 않고 휴가관리에서
  편집한 일정을 그대로 쓴다(`restDayName`).
- 달력에서 공휴일·회사휴무 날짜는 빨간색 + 이름 표시.
- 휴일 근무는 정규 근무가 없어 **시작시간도 입력**(기본 09:00) → 인정 = 종료 − 시작 − 휴게 1시간, 1시간 절삭.
  예) 09:00~18:00 → 8h. 평일은 그대로 종료시간만. `field_overtime_records.start_time`(null = 평일 기록).
- 집계는 평일·휴일 구분 없이 합계만.
- `supabase/migration_field_overtime_holiday.sql`: `start_time` 컬럼 + 실무자 권한 사용자의 `holidays` 읽기 정책.

## 화면

- **달력 탭**: 월요일 시작 달력. 날짜 칸에 `이름 Nh` 칩이 직원별 색으로 쌓이고, 줄 오른쪽에 그 주 합계.
  날짜 칸 클릭 = 그 날짜로 신규 입력, 칩 클릭 = 수정/삭제. 헤더 `+ 신규 입력`은 오늘(다른 달을 보고
  있으면 그 달 1일)로 연다.
- **주차별 집계 탭**: 직원 × 1~5(6)주차 + 합계 행/열. 주차는 달력 한 줄과 같다(`monthWeeks`) — 월 경계에
  걸친 주는 이 달 날짜만 합산한다.
- **월별 집계 탭**: 연도 선택, 직원 × 1~12월 + 합계 행/열.
- 같은 직원·같은 날 기록이 이미 있으면 신규 입력이 덮어쓴다(모달에서 미리 안내).
- 퇴사 처리된 직원은 입력 선택지에서 빠지지만, 그 기간에 기록이 있으면 집계표에 `(퇴사)`로 남는다.

## 직원 명단 = 기술인 주소록 '미래사업팀' (`supabase/migration_team_roster_sync.sql`)

- 원본은 기술인 주소록(`engineer_contacts`)의 소속 `미래사업팀`. 연장근무(제안서팀)·실무자·휴가관리가 같이 쓰는
  `overtime_employees`로 **단방향** 동기화한다. 연결 키는 예약만 돼 있던 `engineer_contacts.employee_id`.
- 동기화는 DB 함수 `sync_team_employees()`(security definer — 주소록 권한이 없어도 동작). 연장근무 두 화면과
  제안서팀 직원 관리 모달이 직원을 읽기 직전에 호출한다(`lib/overtime/teamSync.ts`).
  - 미연결 미래사업팀 기술인 → 같은 이름의 미연결 직원이 있으면 연결, 없으면 직원 행 생성
  - 연결된 직원의 이름·직급(`rank`)·재직여부를 덮어씀. 재직 = 소속 미래사업팀 AND 재직상태 `재직`
  - 삭제는 하지 않는다(근무기록 보존). 정렬순서·기본업무내용·입사일 등은 건드리지 않는다
- 그래서 제안서팀 "직원 관리" 모달은 이름·직급·재직을 읽기 전용으로 바꿨고 추가/삭제를 뺐다 — 명단 변경은 주소록에서.
- 마이그레이션의 1회성 정리: 기존 연장근무 직원 중 주소록에 미래사업팀으로 없는 사람을 맞춘다. 같은 이름·같은 직급의
  소속 빈칸 기술인이 정확히 1명이면 그 사람 소속을 미래사업팀으로(서영빈 사원), 없으면 주소록에 새로 만든다.
  같은 이름이라도 직급이 다르면 동명이인으로 보고 건드리지 않는다(김영준 상무, 김주성 상무).

## DB

`supabase/migration_team_roster_sync.sql` 먼저, 그다음 `supabase/migration_field_overtime.sql` — `field_overtime_records`(FK → `overtime_employees`).
RLS는 다른 메뉴와 같은 `private.menu_permission('field_overtime')` 패턴.
